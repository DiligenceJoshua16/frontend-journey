What I Learned While Studying HTML

When I first started, I thought HTML was a programming language similar to JavaScript. However, as I delved deeper into my studies, I discovered that HTML is actually a markup language designed specifically for structuring the content of web pages.

Core Concepts Covered

  • HTML Fundamentals:

    Learned elements, tags, attributes, headings, and paragraphs.

  • Media & Navigation:

    Learned to implement hyperlinks, images, lists, and tables.

  • Advanced Structure:

    Developed forms, input fields, and standard document layouts.

  • Semantic HTML:

    Learned to write meaningful, accessible code.

Major Challenges

While building guided web projects, I encountered and overcame a few key challenges:

  • Incorrect Element Nesting:

    Initially, I would mistakenly nest elements like lists or navigation blocks inside paragraphs, which results in invalid HTML. I learned to strictly follow proper nesting rules.

  • Structuring with Semantic HTML:

    I struggled early on with page layouts, sometimes omitting headers entirely, placing navigation links after the footer, or forgetting to group content into main and section tags.

I worked through these challenges by embracing my mistakes as learning opportunities. By analyzing my errors and applying those insights, I ensured I didn't repeat the same mistakes in subsequent projects.

Current Capabilities

Now that I have completed my HTML fundamentals, I am able to:

  • Create multi-page websites.
  • Build contact forms.
  • Organize web content semantically for better readability.
  • Import media assets and link to external web platforms.

Next Steps

HTML has provided me with a solid foundation. My next milestone is CSS, which will allow me to elevate the visual appeal, styling, and layout of the websites I have already built.

Understanding Semantic HTML

Semantic HTML means choosing HTML elements based on the meaning and purpose of the content, rather than just how it looks. It clearly communicates the role of different parts of a webpage to both browsers and developers.

Key Semantic Elements

  • header

    Introduces the content of a page or a specific section.

  • main

    Identifies the central, unique content of the page.

  • section

    Groups related thematic content together.

  • article

    Represents a self-contained piece of content that can stand alone.

  • nav

    Groups primary navigation links.

  • footer

    Contains closing information, copyrights, or secondary links.

Why Semantic HTML Matters

  • Accessibility:

    A semantic structure allows assistive technologies (like screen readers) to accurately interpret and navigate a webpage for users with disabilities.

  • Maintainability:

    Writing meaningful code makes the repository clean, highly readable, and much easier for developers to maintain over time.

  • Search Engine Optimization (SEO):

    Semantic HTML helps communicate the structure and meaning of webpage content. This can help search engines interpret the page, although semantic elements alone do not guarantee higher search rankings.

Practical Application

I truly grasped the value of semantic HTML while building a multi-page practice project. I successfully organized the navigation, headers, footers, and individual content sections into a clean, professional architecture.

My Approach to Learning Frontend Development

Learning the Fundamentals

I begin each new technology by studying tutorials, official documentation, and structured lessons. My goal is to understand the fundamental concepts before applying them to increasingly challenging projects.

Strategic Note-Taking

I maintain organised study notes containing explanations and code examples for the technologies I learn. These notes serve as a personal reference, helping me revisit difficult concepts and reinforce my understanding.

Deliberate Practice

After studying a concept, I apply it through targeted exercises and guided practice projects. This allows me to move beyond simply recognising code and develop the ability to write and understand it independently.

Independent Project Building

I use independent projects to apply what I have learned, solve problems, and identify gaps in my understanding. Rather than relying entirely on step-by-step instructions, I challenge myself to make decisions and find solutions independently, seeking guidance when necessary.

Continuous Learning and Improvement

I understand that learning a technology and building projects are connected processes. As I work on projects, I discover new challenges, revisit concepts, and improve my solutions. I use these experiences to strengthen my existing skills and prepare for more advanced technologies.

Progressive Project Development

My approach is to build on suitable projects as I acquire new skills. I begin by establishing their structure with HTML, then introduce CSS for styling and JavaScript for interactivity. As I progress, I will use technologies such as React, TypeScript, and AI integration where they are appropriate for the project.

My Learning Cycle

My learning process follows a continuous cycle: study, take notes, practise, build, review, identify gaps, and improve. This approach helps me develop both technical knowledge and independent problem-solving skills.
